# 三屏 / 四屏支持预案

状态：v1.1.0-beta.2 已实现任意组合、免安装模式与每屏固定分辨率，并通过 459 项离线模拟检查；未启动新版 GUI 或进行真实屏幕测试。原始预案保留作设计说明，2026-10-12；实现状态更新于 2026-10-13。

设备范围：台式机与笔记本的所有受支持物理显示器平等处理。主界面不区分“内屏 / 外屏”，不要求存在笔记本屏幕；任意屏幕都可以独立启用或成为主屏。旧版内外屏含义仅用于迁移旧配置及兼容旧命令。

## v1.0.0 的历史行为

v1.0.0 保存一台目标外接屏。“仅外接屏”只启用这台屏幕；“双屏扩展”只启用内置屏和这台外接屏。其他外接屏会被排除在应用的显示配置外。v1.1 的通用集合选择已取代这个限制。

相关代码：`NativeDisplay.Matches` 将屏幕数限制为 1 / 2，`NativeDisplay.Choose` 只选择 1 / 2 条显示路径；`Config` 只保存单个 TargetPath 和单个 ExternalScalePercent。

继续使用稳定版 v1.0.0 且需要同时使用三、四屏时，应先停用旧版自动守护。新版提供任意选择，但真实硬件行为仍待验证。

## 使用方式：任意选择亮哪些屏幕

屏幕数按实际显示器总数计算，内置屏也算一块；设计同样覆盖关闭内置屏、同时使用三台外接屏的情况。

核心操作是每块屏一个启用勾选框。用户可以直接选择任意非空屏幕集合并应用，不必先命名或保存组合。主屏只能从已勾选的屏幕中选择；没有勾选的物理屏幕关闭。保存组合只用于以后快速调用，不限制哪些组合能够使用。

例如连接 A、B、C、D 四块屏幕：

| 亮屏数量 | 所有可选组合 | 数量 |
| --- | --- | --- |
| 1 块 | A、B、C、D | 4 |
| 2 块 | A+B、A+C、A+D、B+C、B+D、C+D | 6 |
| 3 块 | A+B+C、A+B+D、A+C+D、B+C+D | 4 |
| 4 块 | A+B+C+D | 1 |

四块屏共 15 种非空亮屏组合，三块屏共 7 种。每种组合都能另选主屏、保存各屏缩放与布局；选两块屏并不要求其中必须是内置屏或原先的主外接屏。

普通设置使用逐屏勾选，避免把所有排列生成一长串按钮。提供“全选”“仅保留所选主屏”“应用”“保存为常用组合”；托盘展示用户保存的常用组合。全部取消勾选时禁用“应用”，界面提示至少选择一块屏。

| 组合 | 开启哪些屏幕 | 主屏 | 缩放 |
| --- | --- | --- | --- |
| 游戏单屏 | 只启用指定的外接屏 | 指定的外接屏 | 默认 200%，可调整 |
| 所有外接屏扩展 | 启用勾选的外接屏，关闭内置屏 | 用户选择 | 每块屏分别保存 |
| 全部屏幕扩展 | 内置屏与勾选的外接屏 | 用户选择 | 每块屏分别保存 |
| 自由选择（主要操作） | 任意勾选已识别的屏幕并直接应用 | 从启用的屏幕中选择 | 每块屏分别保存或保持当前 |

例如 A 为内置屏、B / C / D 为外接屏。可以保存“游戏：B”“工作：A+B+C+D”“外接工作：B+C+D”“观影：C”等组合。选择了某个组合，游戏退出或驱动改变显示模式后，程序恢复这个组合。

第一阶段由用户手动切换组合。以后可以选配“游戏启动切到游戏组合、退出恢复先前组合”；自动按应用切换需由用户开启，避免与手动选择互相覆盖。

## 设置界面

- 显示每块屏幕的名称、类型、是否在线、当前主屏和缩放；提供“识别屏幕”按钮，让实物屏上显示对应标签。
- 每块屏都可独立勾选启用，不限制单屏是哪一块，也不限制双屏是哪两块。勾选需要启用的屏幕，指定主屏，为每块屏选择倍率或“保持当前”。
- 直接点击“应用”即可生效；“保存为常用组合”是可选操作。取消勾选当前主屏时，自动从剩余已勾选的屏幕中选一个主屏，并在预览中显示。
- 用户先在 Windows 中摆好左右、上下、竖屏位置，然后点“保存当前布局”，减少首次配置步骤。
- 常用组合可以命名、复制、删除，并从托盘一键切换。保留当前单屏及双屏快捷入口，作为兼容快捷选择；主设置不围绕固定单屏 / 双屏按钮组织。
- 新布局首次应用提供“保留 / 还原”与 15 秒自动还原倒计时；确认后才开启持续守护。日常纠正已确认的组合不再反复询问。

## 每个组合保存的内容

- 被管理和启用的显示器身份，以及主屏身份和主屏缺失时的替补顺序。
- 各屏的相对位置、方向、目标缩放倍率。分辨率和刷新率默认沿用可用配置；如增加锁定选项，应明确由用户开启。
- 显示器换接口后，用设备身份重新匹配，不依赖 Windows 的“显示器 1 / 2 / 3 / 4”编号。
- 优先以有效 EDID 厂商、型号、序列号关联屏幕；同时保存已验证的设备路径。无序列号、重复序列号或多台同型号屏无法唯一匹配时，请用户指定对应关系，不猜测。
- 持久保存用户期望的组合。某块屏暂时离线时的替补配置单独存在内存中，不覆盖原始组合和原始布局。

## 插拔、合盖及异常情况

| 事件 | 计划行为 |
| --- | --- |
| 拔掉某块副屏 | 使用组合中仍在线的屏幕，压紧因缺屏产生的布局空隙，保留其余屏幕的相对次序 |
| 拔掉主屏 | 按保存的替补顺序选择仍在线的屏幕为主屏；内置屏可用时也可作为替补 |
| 所选屏幕全部断开 | 如有可用的内置屏或其他物理屏幕，保留可用输出；全部不可用时等待连接 |
| 缺失的屏幕重新接上 | 恢复原组合、原主屏、原位置和各屏倍率 |
| 合盖使内置屏不可用 | 暂时移除内置屏，继续使用组合中在线的外接屏；开盖后恢复 |
| 接上未配置的新物理屏 | 暂停拓扑纠正并提示配置新屏，不自行关闭新屏或加入旧组合；完成选择后恢复守护 |
| 同时存在多个虚拟 / 远程显示屏 | 不自动归类为物理外接屏；远程会话暂停守护，检测到可能冲突的虚拟桌面时暂停拓扑纠正并提示 |
| 硬件 / 扩展坞无法支持所选组合 | 应用前验证失败时保留现有配置并显示原因；不反复切换 |
| API 失败或驱动持续争抢 | 恢复可用的先前配置，必要时保留可用主屏；对失败分项限速，避免闪屏 |

三、四屏指用户想保存的组合，程序不能让硬件、接口或显卡支持其无法输出的屏幕数量与时序。需在实际连接上验证可用配置。

## 实现改动

1. **配置升级**：引入带版本号的 DisplayProfile，包含多个 MonitorPreference、主屏和替补顺序。旧单屏配置迁移为单屏组合并保留 200% 等现有倍率；旧双屏配置迁移为内置屏加所选外接屏，并保留现有“不主动改扩展模式缩放”的策略。迁移前备份，可回退。
2. **屏幕身份解析**：每次拓扑变化重新建立身份、适配器、target、source 的映射。多屏共享型号不等于同一台屏；连接身份也不等于固定 source ID。
3. **路径规划**：选择全部需要启用的显示路径。每块扩展屏需要独立 source，键包含适配器和 source ID；以保持活动路径为优先，在冲突时搜索其他可用分配。由 Windows 验证整组配置后才应用。
4. **布局与主屏**：把所选主屏平移到原点，验证不重叠及桌面连通性；屏幕暂失时计算临时可用布局，重连后恢复原布局。
5. **倍率守护**：先恢复拓扑，再用新 source 映射分别读取和设置各屏倍率。倍率失败应独立报告和限速，不因一块屏倍率不支持而拆掉整个已成功的扩展桌面。
6. **状态判断**：比较实际活动屏集合、主屏、位置、方向与被管理的缩放。全部符合时不重复调用切换接口。
7. **防止过期应用**：插拔事件防抖；应用前重查连接状态，连接集合变化就重新规划。每次应用使用完整配置并串行执行，避免多次事件同时争用。
8. **回退**：首次应用与失败恢复都应按当前仍连接的屏幕重建可用配置，不盲目提交已经断开的旧路径。至少保留一块可用物理屏；所有屏不可用时等待。

## 验收

- 内置屏 + 2 台外接屏、内置屏 + 3 台外接屏，以及关闭内置屏的多外接组合。
- 游戏单屏、自定义两屏、全外接扩展、全部扩展之间切换。
- 三块屏遍历全部 7 种非空子集、四块屏遍历全部 15 种非空子集；两屏集合覆盖任意两块外接屏，以及原主外接屏被排除的情况。各组合验证主屏必须属于启用集合，取消最后一块屏不能提交。
- 混合 100% / 150% / 200% 缩放，横竖屏、不同分辨率和刷新率；失败范围不静默换成其他倍率。
- 关闭中间副屏产生的布局空隙、主屏断开及重连、合盖及开盖。
- 换接口、Windows 屏幕编号变化、同型号且无唯一序列号的两台屏。
- 驱动恢复、登录及唤醒、游戏改变拓扑、远程和虚拟屏共存。
- 所选组合超过实际可用的显示路径数量时，现有桌面保持可用。
- 配置迁移、首次应用超时还原、反复失败限速，及单屏 200% 的现有功能回归。

先补配置、屏幕身份、路径规划和模拟测试，再在实际三 / 四屏机器上验证。只有单外接屏的测试环境不能作为多屏功能已经验证的依据。
